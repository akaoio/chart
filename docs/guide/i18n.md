# Languages

The chart speaks whatever language the application speaks, and it ships **no translations**.
Every application has its own set of locales. A library that carried translations would have to
pick which languages it supports, and every application with a language outside that set would
be left half in English. So the work is split:

- **The chart declares** what it says: `dictionary`, a catalogue of keys with English text,
  exported from the package.
- **The application translates**, through two properties on `<chart-canvas>`.

```js
import { dictionary } from "@akaoio/chart"

canvas.locale = "de"                      // every number and date the chart formats itself
canvas.dictionary = (key, values) => …    // every word — a function…
canvas.dictionary = { notAvailable: "k. A.", open: "E" }   // …or a plain object
```

Both properties reach every element below the canvas, including a chart nested inside another
chart, which speaks its own nearest canvas's language. Setting either one redraws the chart.
Setting neither leaves the chart exactly as it was: the parity suite compares 37 919 values
against the original library with both unset.

## `locale`: numbers and dates

`locale` is a BCP 47 tag. Nothing about a locale is tabulated in the chart; it is asked of
`Intl` at run time. That means any locale the browser knows works, with no data to ship:

| what | from `Intl` |
| --- | --- |
| decimal mark, group mark, minus sign, digits | `NumberFormat#formatToParts` |
| group sizes (`12,34,567` in `hi`) | the same parts, read back |
| where the sign and `%` go (`+1,28 %` in `de`, `+%1,28` in `tr`) | `NumberFormat` with `style: "percent"`, its parts as a template |
| month and weekday names, AM/PM | `DateTimeFormat` |
| compact axis labels (`2M`, `200万`) | `NumberFormat` with `notation: "compact"` |
| durations (`3d`, `3 ngày`, `3天`) | `NumberFormat` with `style: "unit"` |

The locale belongs to one canvas. `discontinuousTimeScaleProvider.setLocale` changes d3's
**global** default and remains for parity with the original. Two charts on one page in two
languages need `canvas.locale`.

## `dictionary`: words

A function gets `(key, values)`. An object is looked up by key. A missing key falls back to
the English in the catalogue, and so do an empty string and an answer that is the key itself,
which is how many dictionary functions say "I don't have this". So an application can hand
over its own dictionary door unchanged. Some sentences have holes, like `bars: "{count} bars"`,
and the locale decides where the hole goes.

The catalogue is the list of keys to translate. An application can check its own translations
against it rather than copying the list:

```js
import { dictionary } from "@akaoio/chart"

const missing = Object.keys(dictionary).filter(key => !(key in myWords))
```

## What the chart formats, and what it does not

The chart localizes **its own defaults** only. A `displayFormat`, `tickFormat` or
`yDisplayFormat` that the application passes is the application's own wording and is never
rewritten. The rewriting reads its input as `en-US`, so rewriting an application formatter
that already writes `1.234,5` would corrupt it. An application that passes a formatter should
format in its own locale.

Text a user typed, such as a note or a callout, is never touched either. Default text that
becomes part of a drawing (`Signpost`, `Callout`, the `Lorem ipsum...` of a new text box) is
translated at the moment the drawing is created, so a saved drawing holds a plain string, as it
always did.

The showcase has the same chart in four languages, with the code that builds it, under
[Cursors & tooltips → Languages](https://akaoio.github.io/chart/docs/showcase/coordinates.html).
