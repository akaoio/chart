# chart

Financial charts as plain Web Components. No framework, no build step.

A port of [react-financial-charts](https://github.com/react-financial/react-financial-charts) —
the most mature open financial charting library for the web — from React to standard custom
elements, so it can be used from any page regardless of what framework that page is (or is not)
built with.

> **Status: early.** The machinery is in place; the things you would actually look at are not.
> The port goes in
> dependency order and each stage has to prove itself before the next begins. See
> [#1](https://github.com/akaoio/chart/issues/1) for the plan and
> [`docs/parity/`](docs/parity/) for exactly what is done, what is deliberately skipped, and
> what has not been touched.
>
> Done so far: `scales`, `core`, `utils`, `axes`, and 11 of the 25 `series` — enough for a
> real financial chart: candles, lines, areas, volume bars, OHLC, scatter, and both axes.
>
> Checked against **11,534 values** generated by running the original library itself —
> including **9,536 canvas drawing commands** compared one at a time — plus **72 assertions**
> driven through a real browser.

## Why a port and not a wrapper

Wrapping React would mean shipping React. The point is a charting library that any page can use
without adopting a framework, and that stays usable in ten years because it depends on the
platform rather than on one library's release cycle.

The port is close to the original on purpose. The maths (via [d3](https://d3js.org)) and the
canvas drawing are kept as they are; what changes is how components find each other and how
redraws are scheduled — the parts that were React's job.

## Install

```sh
npm install github:akaoio/chart
```

ESM, no build step. Import what you need and use the elements.

Loading it straight into a page with `<script type="module">` and no bundler works too, but
the d3 packages it imports are bare specifiers, so the browser needs an import map to find
them:

```html
<script type="importmap">
  { "imports": { "d3-array": "/node_modules/d3-array/src/index.js", "…": "…" } }
</script>
```

## Verifying the port

The port is not checked by eye. `tools/golden/` runs the **original library** in Node and
records what it returns; `npm test` then holds this port to those answers. The same case
files drive both sides, so the only thing that can differ is the result.

```sh
npm test                                               # both suites below
npm run test:golden                                    # port vs recorded answers
npm run test:browser                                   # DOM, canvas and pointer, in Chromium
CHART_SOURCE=~/react-financial-charts npm run golden   # re-record from the original
```

Recorded answers are committed, so running the tests needs nothing but this repo.

Not everything can be settled by arithmetic. From the chart host onwards there is a DOM, a
canvas and a pointer, so that part is proven in a real browser by real gestures — clicking,
dragging, removing an element mid-drag — and by reading pixels back when position is the
thing being claimed.

Both suites are checked in the other direction too: the port is deliberately broken in
specific ways to confirm the tests notice. What was broken, and which test caught it, is
written down in `docs/parity/`.

## Determinism

The chart is driven from the outside: given the same state, it draws the same picture. There is
no hidden mutable state that only the chart can see. This is what makes it possible to scrub a
chart backwards and forwards in step with narration, which is what akao — the first consumer —
needs it for.
